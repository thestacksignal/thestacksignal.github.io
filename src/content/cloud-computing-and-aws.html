Key takeaways

  • Cloud computing replaces up-front hardware purchases with pay-as-you-go use. You pay for what you run, and you can scale up or down in minutes.
  • Cloud services come in three models: IaaS, PaaS and SaaS. They differ in how much you manage yourself.
  • Most beginners need only five AWS building blocks: compute, storage, a database, networking and access control. Learn those first.
  • Cost surprises come from forgotten resources, not from the services themselves. Set a budget alert before you build anything.

What cloud computing actually is

Before the cloud, running a website or an app meant buying servers, placing them in a data centre and hiring people to maintain them. You paid for peak capacity all year, even if you needed it for a few hours.

Cloud computing turns that into a service. A provider runs large data centres and rents out slices of them. You request a server, a storage bucket or a database through a web console or an API, use it, and pay only for the time and capacity you used.

Three ideas explain most of the value:

  • On-demand. Resources are available in minutes, not weeks.
  • Elastic. You can add capacity during a traffic spike and remove it afterwards.
  • Metered. The bill follows usage, so small projects can start cheaply.

IaaS, PaaS and SaaS: the three service models

The model tells you who is responsible for what.

ModelYou manageThe provider managesExample
IaaS (infrastructure as a service)Operating system, runtime, application, dataPhysical hardware, networking, virtualisationA virtual server on Amazon EC2
PaaS (platform as a service)Application and dataServers, operating system, scalingA managed web app platform such as AWS Elastic Beanstalk
SaaS (software as a service)Your own settings and dataEverything elseEmail, CRM or accounting software in a browser

Pick the model with the least management that still meets your needs. Running your own server gives control but also means you patch it, secure it and fix it at 2 a.m.

What AWS is and why people use it

Amazon Web Services is Amazon's cloud platform. It offers hundreds of services, from basic servers to machine learning tools, and it runs in data centres grouped into regions around the world. Each region contains several availability zones, which are separate facilities that let you keep an app running if one has a problem.

People choose AWS for its breadth, its large community and the amount of documentation and tutorials available. The same breadth is also the main difficulty for beginners, because the service list is long and the names are not obvious. The next section cuts it down to what matters.

Most beginners need five building blocks: compute, storage, a database, networking and access control.

Cloud storage on AWS

Amazon S3 is the service most people meet first. It stores files as objects in containers called buckets, and it is commonly used for backups, images, downloads and static websites. Access is private by default, which is the setting you should keep unless a file truly needs to be public.

✓

Keep new S3 buckets private, and turn on the account-level setting that blocks public access. Make a file public only on purpose, and one file at a time.

Cloud computing and AI

Cloud platforms are also where most teams run machine learning and AI workloads, because training and serving models needs large amounts of computing power for short periods. AWS offers managed services for this, and other providers offer similar tools.

How AWS billing works

AWS charges for what you use. The main cost drivers are compute time, storage, data moved out of AWS and some managed services that bill by the hour even when idle.

  • Compute is billed by the time a server runs, so stopping an unused server stops most of its compute cost.
  • Storage is billed by the amount you keep, even if you never open the files.
  • Data transfer out to the internet usually costs money, while data coming in is usually free.
  • Free tier offers change over time, so read the current terms on the AWS pricing page before you rely on them.
!

Set a budget alert before you launch anything. A forgotten server, database or load balancer can run for weeks and produce a bill you did not expect. Create a budget with an email alert in the billing console on day one.

Common beginner mistakes

×

Do not use your root account for daily work. The root account has unlimited power. Create a separate user with limited permissions, protect the root login with multi-factor authentication and keep it for emergencies only.

  • Leaving resources running. Delete test servers, databases and unused storage when you finish.
  • Opening a server to the whole internet. Allow only the ports you need and only from the addresses that need them.
  • Hard-coding access keys in code. Keys committed to a public repository are found and abused quickly. Use roles and environment variables instead.
  • Choosing a region by default. Pick a region close to your users and check that it offers the services you need.
  • Skipping backups. A managed database still needs backups and a tested way to restore them.

A safe 5-step plan for your first AWS project

  1. Create the account and secure it. Turn on multi-factor authentication for the root user, then create an administrator user for daily work.
  2. Set a budget alert. Choose a small monthly limit and send alerts to your email.
  3. Build one small thing. For example, host a static website on S3 with CloudFront in front of it.
  4. Record what you create. Keep a list of every resource so nothing is left running by accident.
  5. Delete it, then rebuild it. Tearing it down teaches you which pieces depend on each other, and it keeps the bill at zero.
